# 智能省额度迁移（Windows 本地开发预览）

当前采用用户明确选择的独立资料项目方案。完整旧对话和索引保存在工作台自己的资料区；Copilot 新增独立资料项目和带“智能搬家”标识的对话。已有工作项目不添加文件、不合并设置，不改全局配置、数据库结构、登录或模型选择。准备不调用模型、不需要新 API Key。此边界指工作台的搬家操作，不是对用户以后主动让 Copilot 执行操作的权限承诺。

## 用户流程

选择来源记录 → 智能省额度迁移 → Copilot 桌面端 → 开始搬家 → 自动请求打开新对话。

智能流程只有“选择软件、确认搬家”两步。确认页仅显示搬到 Copilot、沿用的对话名称及开始按钮；没有目录选择、配置合并、授权勾选或要求核对。点击 Copilot 后先保存完整原文，确认前不写入 Copilot。每条来源对话分别保存为“原对话名称（智能搬家）”，多选也分别出现在 Copilot 列表中；同名而来源编号不同的对话各自保留。

搬入完成后自动请求打开本批对话一次，正常完成页只显示结果、原名称及“完成”，不要求复制话术或处理设置。打开失败才出现“重试打开 Copilot”，重试只打开，不重复搬入。打开后只有一条工作台生成的简短说明，用户输入并发送下一步要求后才会产生模型回复；完整旧消息供按需查找，不伪造 AI 回应。

不再提供独立“搬家记录”管理页。搬过的原记录旁显示“已智能搬家”，点击即可请求打开对应 Copilot 对话；旁边“···”提供按需查原文、可选要求确认、从原档完整搬家与撤销。普通流程不需要这些操作。入口使用已有回执，重开工作台后仍可识别。未确认的旧话仅作参考，不自动变成当前要求。

重复搬家按来源及原记录编号查找已完成入口，复用原资料项目和原对话，保留后续聊天、手动名称和设置。重排多选、重开工作台、部分失败重试都不另建同一条副本；保存时有跨进程锁并再次核对。源头新增消息仅更新工作台原档与索引。已归档、隐藏、关联关系异常或回执损坏时停止，避免偷偷创建同名副本；旧版已经产生的副本不自动删除或合并。

早期直接写入已有工作项目的登记，与现在的独立资料项目分开识别；只有明确旧版布局才跳过新版入口核对，不读取、搬动或修改旧项目。另一条登记损坏时，已严格核实的对应入口仍可直接复用，因为不会新增对话；找不到可核实入口时仍停止创建。登记核对问题会明确说明原记录已保留，不误报成旧对话尚未保存完整。

记录在请求打开前已完成保存；正常项目会话类型为 `project`。工作台先在无活动任务、无未发送草稿且窗口可核实的条件下重新加载 Copilot 列表，再请求本次回执对应的 `ghapp://sessions/<workspace-session-UUID>`，避免只显示正文却没有左侧入口。任务或草稿存在时自动等待，不抢草稿焦点；关闭完成提示后，工作台仍打开时继续等待。暂时无法安全同步则保留记录并显示重试，不冒充已经完成显示。

不会终止或重启 Copilot，不发送提示词。刷新请求和链接请求仍不代表真实客户端显示已通过。旧独立资料项目回执在打开时可修正此前错误的 `workspace` 类型：只改本工作台自己登记的会话类型字段和回执预期，保留所有消息及其他字段；有活动会话、归属不明或未知更新触发器时不更改。

## 存储和保护范围

- `memory/bundles/<稳定编号>/`：完整原始 JSON、可阅读历史分段、中文索引、已确认状态。图片/附件引用保留，但不承诺把实际附件文件或原开发环境搬齐。
- `memory/copilot-workspaces/<随机编号>/`：工作台专用资料项目。归属标记之外仅写入五个小文件：`.mcp.json`、`.github/copilot-instructions.md`、`.agent-memory/manifest.json`、`INDEX.md`、`START_HERE.md`。不建立 Git 仓库，不写 `.gitignore`，不把完整档案再复制到已有项目。
- `memory/deployments/<回执编号>/`：本次写入摘要、备份及撤销状态，不提供给 MCP 工具。
- Copilot 本机保存位置：仅按已知格式新增本次 project/session/workspace 行及其新说明目录。使用事务，不改表结构、旧会话、旧项目设置，不创建 Git 分支、worktree、远程任务或自动批准。

`core/memory_workspace.py` 后端验证资料目录必须位于当前工作台库的固定子目录，随机编号和精确归属标记都匹配，且不经过符号链接/目录联接。准备 API 不接受用户项目路径；规划、安装和桌面登记再次校验。复制标记到任意已有项目也不能绕过路径限制。旧项目配置合并逻辑已删除，不是隐藏同意框后继续合并。

新项目的只读服务只接收自己的 memory root，从已验证位置推导工作台资料库；按清单里的合法包编号检索主档案。不会接受调用方指定任意文件路径。旧预览独立资料项目可以复用，早期多条合在一起的入口也不拆散、不改名、不删聊天。打开或复用时，只在归属及原文件摘要匹配后将早期 MCP 配置的 `type:stdio` 校正为 Copilot 的 `type:local`，同步自己的清单和撤销摘要；写入失败恢复、用户修改拒绝覆盖。不自动处理旧预览曾写入的已有工作项目。

## 实现

- `memory_store.py`：无损原档、稳定消息编号/父消息关系、SQLite FTS5 中文检索、候选/确认/已取代状态。未展开内容引用、更短的重复导出拒绝覆盖；增量重建先在暂存目录成功再替换。
- `memory_server.py`：标准 stdio JSON-RPC MCP；仅 `search_history`、`read_history`、`get_current_state` 三个只读工具。分页限制返回量；不提供任意路径读取、删除或执行工具。
- `memory_deploy.py`：只规划本工作台资料项目，复用已完成入口、跨进程安装锁、写前核对、原子替换、本地服务握手、失败恢复和撤销。后续修改过的受管理文件拒绝覆盖。完整档案留在主库，没有主库和项目档案副本的同步负担。Copilot 本地 MCP 配置采用 `type:local`，服务传输仍为 stdio。
- `memory_desktop.py`：先检查结构与必填字段，事务只插入本批记录；未知触发器的额外写入拒绝。只查询本资料路径的必要项目元数据，不读认证和旧聊天。
- `memory_jobs.py`、`main.Api`：复用原来源导出；确认要求为完成后的可选操作，只更新工作台索引，已运行只读服务下次查询即可看到，不写 Copilot 设置。完整迁移退路直接读已保存且校验通过的原始 JSON，不再从来源导出。

`CURRENT_STATE.md` 和 `get_current_state` 只列用户确认内容；关键词规则仅提候选，不声称模型语义理解。可选面板显示各包前 100 条，其他条目仍作为历史保留。重要结论按原消息核对，旧工具调用不重新执行。

撤销先整体核对本次文件和桌面登记，再移除自己的新增内容；有新消息、附加文件、关联工作区或后续项目设置就停止，保留用户工作。工作台完整原档和已确认要求不因撤销丢失。旧预览回执的撤销兼容仍保留。

## 构建与验收

`python scripts/build_memory_preview.py --output <独立目录>` 重建记忆服务、搬家程序、原续跑组件和 WPF 外壳；固定基线/引擎、源码摘要、冻结合成检查、WPF 自检及包内容核对全通过后才复制交付。不安装、不覆盖正式版本、不发布 GitHub。

`development-preview.json` 标记本地预览，使用独立工具配置，关闭正式更新和续跑自动恢复。基线仍是 master `644fc12372b57102e40a7137b95c7c8294e05a64` / Windows v0.3.16；无提交、推送、标签或 Release。原完整搬家和续跑业务保留。

源码/真实页面桥、冻结服务握手、官方组件只读恢复、真实客户端加载检索、模型续聊、实际额度对比是不同层次，前几层不能替代后几层。本轮只用隔离合成数据，不读真实认证/聊天，不发送模型请求。真实 Copilot 的检索启用、续聊效果与节省量仍待验收，Mac 智能冻结包未验收。
