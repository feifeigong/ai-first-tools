# Mac 状态、历史日历与开关联动修复

2026-10-29，目标版本 Windows 0.3.23 / Mac preview.26。

## 修正

- Finder/launchd 没有终端 UTF-8 语言环境时，BSD ps 会转义中文路径。续跑及提醒共用固定 UTF-8 的指定 PID 元数据读取，仍核对内核启动时间、实际映像、完整参数和所有权；不读取进程环境。无关进程复用旧 PID 不能阻止新监测，也不能被停止。
- 历史发现接口的文字可能是摘要。新增明确的 discoveryOnly 来源标记，仅用编号发现原帖；分类、作者、时间和引用/回复关系仍核对 X 原文。实时原文源的正文一致性保护继续保留。DiscoveryRevision 4 清除旧检查队列的来源假设，不清除已提醒记录。
- 两端嵌入同一份公开历史，首次离线即可展示；不标记最新成功、不制造通知、不推断个人额度。缓存中已有条目优先，历史仅补缺；30天前的历史自然退出。每个来源请求有8秒上限，避免一个卡住的来源吃完45秒总预算。
- Mac 日历打开后立即绘制，前90秒更快读取本地后台进度，不增加网络轮询。状态读取会恢复已启用但尚未启动的提醒。
- 关闭续跑同时关闭用卡，子开关置灰；重新开启续跑不自动打开用卡。独立计时保留，只有续跑和计时都关才取消自启。页面明确写出下次登录运行什么。

## 验证边界

合成检查覆盖历史摘要和真实含义不同、摘要伪造确认、原帖作者错误、关联证据错误、即时离线历史、过期历史、无新鲜度/无重复提醒、中文路径元数据、复用 PID、开关与自启组合。Mac 原生发布门槛新增 C 语言环境下的实际冻结续跑与提醒身份检查，以及冻结包离线历史检查。

所有账号、数据库、工作聊天测试均使用隔离合成资料。不读取真实聊天/认证，不发真实模型请求，不用真实卡。公开历史补查只请求公开站点和 X 官方嵌入，证据仅含公开帖子。原生构建、原生检查和发布资产通过后再记录交付结果；Windows 浏览器检查不能替代 Mac 原生验收，也不等于真实账号计时或目标客户端续聊已通过。
