# 自动开启 5 小时计时

此功能随 Windows 0.3.22 / Mac preview.25 开发，发布状态见首页下载入口。

在「续跑与重置」打开「自动开启 5 小时计时」。它默认关闭，独立于自动续跑：关闭续跑后，若计时仍开启，计时请求仍会执行。请求会消耗少量套餐额度。

工具优先让正常任务继续。已有官方返回的未来恢复时间、正在续跑或刚开始正常使用时，不额外发送请求。确实需要启动新周期时，在临时空白会话发送一次“只回复 OK”，之后重新读取官方恢复时间。只有请求完成且同一额度窗口返回新的合理时间，才显示“本轮计时已开始”；不会自行加五小时。

临时会话使用 Codex 的 `--ephemeral` 能力，不进入持久聊天历史，不复用或修改工作对话。忽略用户项目配置和项目说明，使用只读限制，关闭 shell、插件、应用及相关工具功能；请求中不携带工作文件或聊天正文。该功能不调用使用重置卡的接口，也不切换为 API Key 计费。

当前只接受官方明确返回的 `codex` 单一额度类别、300 分钟窗口及可核对的周额度。使用账号模型列表里可用的 GPT-6 Luna 和其最低支持推理档位，标准速度；没有这个轻量模型、存在多个无法确定关系的额度类别、额度信息不明或周额度不足时，不换成更大的模型硬试。无 5 小时窗口的账号不适用。

每轮在发送前保存一次记录。电脑重启、工具更新或发送超时后，不会盲目重复这轮请求；结果不明显示“计时未确认”。明确在模型请求发出前失败的登录、模型发现或连接检查，间隔至少十分钟后可再检查。保存记录无法读取时保留原文件并暂停计时请求。

关闭工具箱窗口后，已开启的功能继续运行。「登录后自动运行」控制下次登录是否恢复这些功能；电脑关机或休眠期间无法执行。续跑和计时都关闭时，同时取消登录自启。Tibo 重置提醒仍由自己的开关控制。

## 续跑与用卡的关系

| 设置 | 行为 |
| --- | --- |
| 续跑开启、自动用卡关闭 | 等待自然恢复或官方重置实际到账，再继续被限额打断的任务。 |
| 续跑开启、自动用卡开启 | 只有确认周额度达到 100% 且有可用卡时才尝试用卡，到账后继续。5 小时限额单独用完不触发用卡。 |
| 续跑关闭 | 不继续工作任务，也不为续跑自动用卡；保留用卡偏好。计时若单独开启，仍可能发送那一次极短请求。 |

提醒里的「关闭自动用卡」只关闭用卡权限，保留续跑、计时和登录自启选择。新闻公告或计算时间不等于个人额度到账；继续任务仍需读取账号额度。

## 验证范围

开发与 CI 只使用隔离合成资料、假客户端和原生只读组件检查，不读取真实聊天或认证，不发模型请求、不消耗真实重置卡。因此这些检查证明开关、请求参数、去重和时间判定保护，不能冒充真实账号已成功启动下一轮计时。真实账号的适用性以运行时官方返回为准。

官方参考：[非交互临时会话](https://learn.chatgpt.com/docs/non-interactive-mode)、[账号额度字段](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。
