# Copilot 完整搬家索引兼容修复

## 当前状态

2026-11-02：候选 Windows 0.3.24 / Mac preview.28。运行包需通过两端构建和冻结检查后发布；源码通过不代表用户真实客户端已经验收。

## 问题与依据

用户先遇到项目会话的 `Worktree missing`，经其他工具修复后可打开，再完整搬入新记录却提示“正在占用索引或数据格式已变化”。两种提示不能混为一谈：前者涉及项目工作区/工作目录关联，后者是工具箱写入新会话失败。没有核对用户真实数据库，不能推断其他工具具体改过什么。

仅检查本机公开 Copilot 1.1.33 程序文件的静态 SQL（SHA-256 `64ee22d572f0627a830bd8c60995693014b27da7031b0510607561895764d63b`），发现它与此前已核实的 1.1.31 一样，包含将 `agents` 改为 `persistent_projects` 的官方迁移和对应条件触发器。未读取真实 DB、聊天、认证、Cookie、环境转储或私人项目。

智能搬家已经精确识别新触发器，完整搬家却仅识别旧 `agents` 规则。SQLite 即使不会执行 Agent-only 分支，也会在编译 INSERT 时授权该分支；完整搬家的授权器因此报 SQLITE_AUTH。隔离的官方形状夹具复现了同样的失败，不依赖用户修复过的数据。

## 修复与保护

- 两种搬家共用精确触发器定义，旧 `agents` 和已核实的 `persistent_projects` 规则都支持。只允许普通聊天/项目写入中不会执行的官方 Agent-only 分支；不启用 Agent，不放宽未知触发器。
- 完整搬家仍仅新增 `general_chat` 和对应历史目录，不创建 worktree、不改项目/工作区/旧记录、不改表结构或触发器。未知条件、附加写入、必填字段变化仍拒绝。
- 将索引锁定、规则不支持、格式不支持和文件保存错误分别提示。规则不兼容不再笼统要求“结束任务后重试”。不显示原始 SQL、正文、认证或路径。
- Windows/Mac 共用业务与冻结检查；正常去重、完整回读、来源只读、失败仅回滚本次写入的保护保持。

## 验证

修复前三项新回归失败，证据保存在本机隔离构建目录；修复后 Copilot/智能搬家相关 72 项通过。用合成的旧项目和不存在的 worktree 关联验证完整搬家仍可新增普通聊天，所有旧行、项目、工作区、表结构和合成凭据哨兵不变。改坏条件仍拒绝，无残留行或文件；真实锁事务得到单独占用提示。

固定摘要的官方测试组件对旧/新两种索引均通过完整分页读取和禁止修复的严格恢复，包含 125 轮、图片、思考和长工具历史；没有向模型发送消息。此结果不等于已登录 Desktop 全量显示、MCP 启用或付费续聊通过。

冻结包新增 `current_full_chat_registration_without_worktree` 与 `unknown_full_chat_trigger_still_denied` 两项检查；Windows 0.3.24、Mac preview.28 的发布校验都必须包含它们。运行包与发布核验结果待通过后补记。
