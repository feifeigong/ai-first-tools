# 软件内更新

## 2026-11-10：0.4.5 双平台对话搬家

Windows v0.4.5 与 Mac 0.4.5-preview.33 由同一次发布请求一起构建。已安装且支持软件内更新的用户，在对应平台检查到新版本后点「下载并更新」。Mac 仍为未签名、未公证预览版，按芯片选择 DMG。源码提交本身不会改写已经安装的程序。

本版把 ZCode、Codex 的可见对话复制到 DeepSeek 官方桌面端或 DSH 社区版。Windows 上正在打开的对应窗口会重新打开并显示新记录；Mac 使用同一套复制代码，打开对应软件后查看。隔离合成记录用于写入回读，不读取真实会话、认证或数据库，不发送模型请求。两端构建通过并核对下载文件后才会公开安装包。

## 历史更新机制

v0.3.16 已发布：安装版在窗口仍可使用时先从已验证安装包暂存新版；安全关闭后，只备份/替换实际变化或损坏的文件。真实文件摘要、卸载程序、额外文件保护和回滚保留。安装包解包更快但体积增加。旧版升到本版仍由旧 helper 执行，新准备逻辑从后续更新生效。完整包验收与各环境实测见 [UPDATER-QA.md](UPDATER-QA.md)。

2026-10-18 v0.3.15：Windows helper 显示实际六阶段和已用秒数，重复启动工具箱时通过当前用户、当前安装专属的通信管道唤回已有更新窗口。安装成功后先释放更新锁、重开工具箱；旧备份、暂存包交给既有后台清理，不再等待数百 MB 文件删除后重开。校验、备份、占用检查及失败回滚不变，仍为全量包。已安装旧版本运行的是它自己随包的 helper，不能因为发布新版就立即获得这些改进；新 helper 在用户升级后生效。

本机该次 0.3.13 → 0.3.14 的完成标记与重开时间显示，替换阶段约 49 秒，完成后约 4 秒重开，目录约 637 MB / 1257 文件。没有原始下载开始时间，不能把用户感知的全部等待都归为这段替换，更不能据此承诺所有设备几秒完成。隔离原生 helper 已实际完成旧测试包到新测试包的替换和新窗口重开，旧备份与额外文件保留；未替换用户正式安装。发布结果另记于 UPDATER-QA.md。

## 用户怎么用

Windows v0.3.7 起，打开软件即可后台检查更新。发现新版时只在顶栏露出一个「↑ 更新」按钮（v0.4.2 起与 Magpie 一致：不再同时弹出第二个提示条，避免两个入口），点一下立即完成下载、校验、更新与重启，不需要手动安装一遍。进度、取消与失败说明都留在底部同一条提示里，下载完不点则一直等着，不打扰使用。新工具跟随新版工具箱一起交付，不需要添加插件。

Mac preview.3 起支持同类流程，当前公开为 `0.4.5-macos-preview.33`，包含自动提醒调度、初始化恢复、失败重试及完整长对话分页，见 [Mac 一键更新](MACOS-UPDATES.md)。两平台包各自匹配，不能用 Windows 版去安装 Mac 更新。

- 只检查版本，不悄悄安装。下载前需要用户点击；下载中能取消，仍可使用工具。
- 下载完成后等待工具安全关闭。正在搬运、未保存或工具拒绝关闭时，停止重启，提示先处理任务，不强杀进程。
- v0.3.16 起，安装版在旧窗口仍可使用时先从已校验安装包准备新版文件，再安全关闭并只替换发生变化的文件；旧版 helper 仍沿用静默安装。免安装版也只替换实际变化的发布文件，不另装一份。
- 完成后自动重新打开，并显示已更新的版本。网络错误不影响原版使用。
- 只操作程序文件与更新缓存，不迁移、不删改任何 Agent 对话或工具箱用户设置。免安装更新拒绝覆盖与新程序文件重名的用户额外文件。
- 文件写入失败时尝试恢复备份；被占用、断电、磁盘损坏等情况不保证自动恢复。失败时保留更新缓存里的备份，可以重新安装完整发布包。更新不能替代个人数据备份。

v0.3.6 及更早的 EXE 没有后台更新代码，必须先手动安装一次新版，此后的升级才可以在软件里完成。

## 软件如何知道更新

软件使用自己的三段版本号，例如 `0.3.7`，查询固定公开仓库 `feifeigong/ai-first-tools` 的 GitHub Release 列表，以数字比较版本，选择比自己更新、已正式公开且包已完整上传的 Release。当前产品为预览版，因此公开的预览 Release 也会被检测；草稿不检测。

Windows v0.3.11 启动三秒内联网检查，不再用上次的“没有新版”缓存跳过查询。持续运行每十分钟复查，返回窗口、恢复连接或从睡眠唤醒时补查（至少间隔两分钟，遵守失败退避）。普通失败按 1/5/15/60 分钟重试，限流等一小时；首次自动失败提示，恢复后主动显示新版及下载按钮。同一版本关闭提示后不反复弹出，顶部入口保留。清理旧更新缓存不再阻塞启动检查。

Mac preview.8 起组件就绪约两秒后检查、持续运行每十分钟补查，并在返回窗口/恢复连接时补查。preview.14 为初始化与更新查询的桥回复增加 10/30 秒超时恢复，避免回复丢失使自动检查永久停住；迟到的旧响应不能撤掉新的下载提示。失败原因可见并自动重试。GitHub 不可达、限流或下载失败时不覆盖旧版。

**提交源码、推送 commit 或只打 Git tag 不会让用户收到更新。必须公开包含本平台完整运行包与校验文件的新 Release。** Windows 需要安装 EXE、免安装 ZIP 和 `SHA256SUMS.txt`；Mac 需要与芯片匹配的 DMG，两架构资产与验证报告完整后发布。更新器直接读取 GitHub Releases，无需维护另一份“最新版索引”。

元数据、下载及跳转仅走 HTTPS 的 GitHub 与其指定资产域名。下载核对 GitHub digest、`SHA256SUMS.txt` 的哈希、包长度和包哈希；ZIP 还检查目录穿越、链接、重复文件、解压大小及清单中每个文件的哈希。这是完整性与固定来源检查，不等于购买代码签名证书，也不能防范发布者账户被攻破。

## 发布者以后怎么发新版

1. 修改代码后，同步 `workspace/AIFirst.Workspace.csproj`、`macos/version.json` 与 `workspace/assets/whats-new.json`。Windows 打包脚本默认从项目读取版本，不另写固定版本。目录中的工具由 `workspace/assets/tool-catalog.json` 统一登记。
2. 对同一源码执行两平台回归和打包。发布包不得包含用户配置、对话、日志、认证文件或私有截图；检查主程序、包清单、更新摘要与原生报告的版本一致。
3. 为 Windows 与 Mac 分别准备对应版本的草稿 Release 和指向本次已验证源码提交的 lightweight Git 标签；已有标签不得移动。Windows 须包含安装 EXE、免安装 ZIP、`SHA256SUMS.txt` 三项；Mac 须包含 Apple/Intel DMG、两架构原生报告与校验文件。只能暂存各自通过验证的同一次构建产物。
4. 两平台均成功后，独立下载核对报告、实际资产的大小/digest/哈希及源码标签，再公开两个 Release。暂存绿色状态可能只是跳过，必须核实完整资产实际存在；源码来源取 Git 标签。读者下次检查即可看到。公开的同版本包不要替换；需修复就提高版本号另发 Release。
5. 公开成功后同步 README 的下载链接、QA 与交接，在此之前标为待发布。Windows v0.3.6 及更早、Mac preview.1/2 仍须先手动安装完整新版；不能把新代码当作旧程序已具备更新能力。

Windows 识别 `v数字.数字.数字` 标签与 Windows x64 资产；Mac 使用 `v数字.数字.数字-macos-preview.数字` 标签并按 Apple/Intel 芯片选择 DMG。新增其他版本后缀或架构前，须先扩展对应解析和渠道规则。

## 本地验证

`--self-test` 包含离线合成 Release、假 HTTP 响应、正确/损坏下载、取消、跳转、解压安全、文件替换与故障回滚等检查，不下载安装真正的新版本，不访问用户对话。

真实更新验收应使用隔离程序目录：旧版启动 → 提示更新 → 下载与校验 → 工具安全关闭 → 后台更新 → 新版自动打开，另测占用、网络中断、校验失败、用户额外文件与失败恢复。安装版验收不要覆盖其他用户正在使用的安装目录；发布前还需在干净 Windows 环境测试。

开发者可先在本地构建两个隔离版本并准备 `workspace/tests/WindowFixture`，再运行 `scripts/prepare_update_fixture.py` 生成无真实搬家工具的测试目录；不要为测试公开假版本。隔离旧程序以 `--config <隔离配置> --update-fixture <隔离新版目录>` 打开，可检查完整界面；`--update-handoff-test` 配合上述两个参数及 `--report <报告路径>` 可程序化检查下载、校验、交接和重启。安装位置不允许 fixture 模式，交接测试还要求包内带 `WorkspaceWindowFixture.dll`；不要把这些开发参数当成用户的更新入口。

更新缓存位于当前用户本地应用数据下的 `AI一手工具工作台/updates`。失败的备份不自动删除；成功后删除已使用的安装包、暂存文件和备份，后台更新程序的运行文件随后清理。
