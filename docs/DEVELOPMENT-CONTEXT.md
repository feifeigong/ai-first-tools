# 完整开发背景、产品决策与架构

本文件供作者、协作者和新的 AI 编程对话接手使用，记录决策和边界，不把旧设想当成已完成能力。

## 项目由来与演进

最初是「对话搬家」：复制不同 AI Agent 的历史，特别是 WorkBuddy、WorkBuddy AI、千问办公等国内软件与 Cursor、ChatGPT 本机任务之间的迁移。底层采用 txcript 的修改版，保留上游许可证和完整源码，新增国内适配、本机登记、导入报告和测试。

用户遇到过“生成文件但 ChatGPT 找不到记录”，因此不能只以文件存在判定成功。现在额外校验本机数据库结构、登记项目/模式/历史、备份并回读；格式变化直接拒绝，不强行写入。

ChatGPT 普通云端 Chat/Work 不可写，本机 Work/Codex 分开；Claude 普通聊天与 Cowork/Claude Code 分开。豆包本机轨迹不等于服务器正式会话，不能因为能生成某种文件就宣传原生搬入。

随后作者希望把自制工具集中到带 AI一手品牌的工作台，面向非技术读者。下载包应能直接运行，不要求读者拉代码、配置环境或理解内部进程。

## 固定的产品原则

1. 这是作者自制工具工作台，不是插件市场；不增加添加 EXE、管理插件、内部/外部打开入口。
2. 打开直接显示工具，一个窗口；切换保留状态，不让子窗口先闪出再拼接。
3. 用作者给定 AI一手 Logo 和已确认透明资源，不重新设计、不加白底外框。搬家外层/内层同一标记。
4. 用实际 Agent Logo；名称与版本/模式说明上下排列，ChatGPT 不用字母缩写代替。
5. 侧栏真正隐藏，展开/收起标记不同；鼠标不残留蓝框，但键盘 `focus-visible` 可见。
6. 简单中文步骤：选来源和记录 → 选目标/模式 → 选文件夹 → 确认。
7. 只复制，源记录保留；不迁移项目文件、附件、认证、模型权限、运行环境。
8. 搬运中不可强退/更新，异常必须说明，不报虚假成功。
9. GitHub 公开源码与安装包；Mac 不上商店，不用 Developer ID 签名/公证，如实说明首次拦截。

## Windows 架构与状态

`workspace/` 是 .NET 8 WPF 外壳，通过 Win32 承载现有 pywebview 工具。隐藏启动握手、统一任务栏图标、关闭保护解决闪窗和多个图标。

当前公开 Windows v0.3.8，含安装版/免安装版与一键更新。构建源码 c1f5b97，真实安装与独立资产核对见 UPDATER-QA.md；后续文档/发布流程提交不等于重做二进制。v0.3.6 及更早需手动安装一次，已使用 v0.3.7 可软件内升级。

更新后台比较 GitHub 版本；仅接受完整且校验通过的 Windows 资产。安装版静默运行安装程序，便携版事务性覆盖发布文件，失败提供恢复保护，不触碰 Agent 数据、不强停工具。原理与验证见 `UPDATES.md`、`UPDATER-QA.md`。

## Mac 移植选择

WPF/Win32 不能移植到 macOS，更不能改 EXE 后缀。保留 Windows，新增 `macos/` 的单个 Cocoa/WebKit 窗口。

`prepare_macos.py` 在构建目录包裹共享页面，不复制出另一套搬家 JS。Python API、分组、弹窗、任务和修改后的 Rust 引擎仍共用。Apple Silicon 和 Intel 在 GitHub 对应真实 Mac runner 编译，自带运行组件形成 APP/DMG。

首版 `0.4.0-macos-preview.1` 与 Windows 下载分开；Windows 更新器不把缺少 Windows 完整资产的 Mac 发布当成更新。Mac 首版是后台提醒、检查更新与下载入口，用户退出后替换应用，尚无自动覆盖更新。

2026-10-12 的首批两架构包在 macOS 15 原生构建，隔离导入、冻结资源、Cocoa 窗口/桥和 DMG 检查通过。首轮发现的空测试账户与加载时序问题、复测链接及后续真机验收边界见 `MACOS-QA.md`；不要重复发布失败或被替代的构建。

2026-10-13 作者反馈检查更新连接失败、Mac 豆包工作没有显示。preview.2 修复 Mac 豆包的 Default 目录识别，并将同一工作区传给导出引擎；刷新同时重新寻找来源。更新 HTTPS 改用系统证书而非打包机器的 Python CA 路径，保留系统代理、严格证书校验和可信仓库过滤，失败显示脱敏分类与下载页入口。新增冻结应用真实 HTTPS 检查，弥补首版未测这一层的缺口；作者 Mac 的具体网络原因仍需新版提示确认。构建结果以 MACOS-QA.md 为准。

2026-10-13 后续需求已发布：Windows v0.3.8 和 Mac preview.4 都用“下载并更新”按钮，有新版自动显示，点一次下载、校验、安全替换并重启。Windows 沿用已有更新器，忙碌时提示任务完成后重试；Mac 自动等待搬运结束，新增独立 helper、系统原子交换和失败恢复。Windows 干净 runner 的真实安装/覆盖/卸载 6 项及安装后 62 项自检通过。Mac 一键更新最初在 preview.3 加入；当前 preview.4 构建源码 7dcc96f，两次完整原生构建的两架构各 73 项单测及四类冻结检查通过，独立核对同次构建的 11 个上传资产后公开。构建末尾初次暂存权限问题独立修复，没有将失败程序包公开。preview.1/2 须最后一次手动换成 preview.4；preview.3 可以软件内升级。详见 UPDATES.md、MACOS-UPDATES.md、MACOS-QA.md、UPDATER-QA.md，当前状态仍以 Releases 为准。

preview.3 发布后追加构建出现 WebKit 偶发未加载，未覆盖其公开资产。996cfb4 仅修订审计模式：业务 home() 与回执单独隔离，不改系统 HOME；ARM 通过但 Intel 仍失败。检查锁定 pywebview 的 Cocoa 实现后，7dcc96f 将启动改为不异步清理共享 WebKit 存储，显式保留随机本机端口，另发 preview.4，不移动旧标签或替换旧包。正常业务仍使用真实用户目录，自己的页面缓存可能保留，不读取其他 Agent 登录数据；同源码两次两架构原生重启均通过。公开匿名列表实测 preview.3 选择 preview.4、同版本无提示，Windows 仍只选 v0.3.8。具体证据及未验收项见 MACOS-QA.md，不把受控审计说成用户安装的公网升级或全部 Agent 验收。

2026-10-14 用户确认 Mac 仍为 preview.2，启动未提示而手动能查到新版。旧标签的自动错误静默、一次性查询有缺陷；preview.4 虽有六小时检查，失败仍静默。新增首次非阻塞错误提示与 1/5/15/60 分钟退避，先在合成 API 中复现再验证修复。preview.5 首轮通过但重复 Intel 窗口检查失败，没有公开；确认桥注入期间存在提前调用的安全时序缺口，追加原生就绪信号后另发 preview.6，构建源码 9703d4335043526fe3ad0ecb00fdba6e31b83ac4，两轮两架构各 74 项单测及四类冻结检查通过，11 个上传资产独立匹配后公开。源码和 Windows 回归同时上传，Windows 安装包仍为 v0.3.8。作者已安装的 preview.2 不会随提交自动改写，仍需最后一次手动换到 preview.6；preview.3/4 可以软件内更新。不能断言用户当次具体网络原因或全部原生客户端均验收，证据与边界见 MACOS-QA.md。

## 安全和真实验证

数据库结构先检查，登记前备份、事务内验证。第三方存储回滚能力不同，不能承诺全部迁移全局原子。源数据库只读，导出临时规范文件再导入，验证后才登记成功。

测试只用临时目录与合成记录，不读取/提交真实认证、Cookie、聊天、完整个人路径、环境全量转储。没有云端认证但有本机任务不应隐藏入口。

构建、窗口可打开、回读、原生软件显示、下一轮对话是不同层次。不要称全部已测试；不自动发付费模型请求。打包工具可能生成 Apple Silicon 必需 ad-hoc 签名，但不是 Developer ID、公证或苹果审核。

新对话先读 `MACOS-HANDOFF.md`，检查 Git 和 CI，按用户现象定位模块。不要重写已验证业务、反复导入、放宽安全检查或关闭系统保护来掩盖问题。

## 2026-10-14：Cursor → Mac 本机 Work 长对话分页修复

用户报告尾部可见、上翻一直重试；同一 Cursor 记录搬到 WorkBuddy AI 完整。旧测试只覆盖两条消息和全量 `thread/read`，不足以证明分页正常。隔离 125 轮 Cursor 合成数据库 → 搬家 → 原生引擎实验中，旧 `history_mode=legacy` 的 `thread/items/list` 确实报 `-32601 / not supported yet`。

`core/codex_import.py` 现在把 txcript 的协议记录转换为有 `item_completed`、稳定 UUID 轮次/消息编号、起止事件、连续 `ordinal` 的 paginated 历史，数据库模式与文件一致。保留协议 `response_item`，让 ChatGPT 自己在打开/恢复线程时建立分页投影；不手写它的 `thread_history_1.sqlite`，也不在用户机器后台启动原生引擎。记录登记前完整比较正文，而非只检查回读非空。工具结果不充当用户新轮次，重用工具调用编号不会导致消息 ID 冲突。

去重增加导入格式版本：旧成功记录允许一次安全重搬为新副本，之后正常去重。源记录和旧目标副本均保留，不自动覆写用户已继续聊过的记录。重新搬入后打开新副本，不要继续打开旧那条。

Mac preview.7 构建增加固定校验值的官方 Codex 0.162.1 测试引擎，只用于两个 Mac 架构的隔离原生分页回归，不打包给用户。测试请求白名单仅初始化、读取、列表、恢复，不允许 `turn/start` 或登录请求。不读取真实认证/聊天。完整 125 轮、250 条带多行长正文、分页游标、单条锚点、思考与重用工具调用都验证；原生桌面人工滚动和付费下一轮仍必须分开说明。

已公开 preview.7，源码标签 `12aa483b9191ee4772cbfaa288dd9429a23f047f`，实际运行包来自 `38527937388 / attempt 2`，两架构各 80+3 检查与四类冻结检查通过；同源码标签构建 `38527943205` 也通过。首轮主分支 Intel 的更新后 WebKit 加载超时，失败产物未发布，细节保留于 QA；不改无关 UI、不放宽校验、不承诺启动永不失败。11 个上传资产与独立下载的原构建逐个匹配后公开，生产公开更新选择与 SHA 清单下载验证到新版。Windows 仍发布 v0.3.8，本轮修复只放 Mac 包；共享修复源码已上传。
