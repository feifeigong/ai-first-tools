# Codex 自动续跑控制页

## 0.3.22 / preview.25 独立自动化选项（候选）

自动续跑负责额度实际恢复后继续任务；其下「周额度用完时自动使用重置卡」独立决定是否允许用卡。关闭用卡不关闭续跑，可以等待自然或官方恢复。续跑关闭后不再继续工作或为续跑用卡，保留用卡偏好。提醒里的按钮也只关闭用卡。

新增默认关闭的「自动开启5小时计时」，与续跑独立；会消耗少量额度，不调用重置卡，不复用工作聊天。是否开始新计时以官方返回为准。登录自启控制已开启的功能；续跑和计时均关闭时才同时取消自启。完整规则和适用范围见[计时说明](FIVE-HOUR-TIMER.md)。后续历史段落描述旧版行为，以本节及实际发布版本为准。

## 0.3.21 / preview.24 自动用卡门槛

自动续跑开启时：5小时额度单独用完，等待Codex返回的恢复时间，不使用重置卡；确认周额度使用率达到100%且有可用卡时才尝试用卡，用卡前重新读取额度。99%和99.9%仍算有剩余，不提前调用。若重新读取时额度已恢复或无卡，跳过用卡。

自动续跑关闭时：不等待后自行继续对话，不自动使用重置卡，同时取消开机自启。Tibo提醒为独立功能，不会因此自动用卡。此修复不改变既有开关和配置；两端共用同一业务代码。

## 2026-10-22 本地预览修复（已构建，待切换验收）

用户只需打开「自动续跑」开关；工具负责等待额度恢复并继续原对话。内部需要持续等待的程序由工具箱管理，不是用户需要另外打开、安装或维护的工具。查看这个页面只读取状态，不会自行启动续跑；退出工具箱窗口也不等于关闭已经开启的续跑。

本轮针对预览中点击后提示“没有保持运行”的故障修正了启动和状态处理。现在等待启动准备完成，最长 15 秒；操作失败后重新核对状态并给出简单、可恢复的提示，不直接要求重装。Windows 通过系统文件锁保证同一份状态只运行一个实例；两个工具箱包只读核实归属后复用同一实例，明确点击开关可启停，但另一预览更新或卸载不会停止正在使用的实例。停止使用正常退出请求，不强杀。

额度判断、发现等待中的会话及真正提交续跑的逻辑保持基线。原包的单路径隔离检查也通过，不能据此认定截图中的具体根因已经找到；没有读取用户配置或运行真实会话来确认。新的独立预览已经构建，通过 Python、PowerShell、实际冻结组件启停、WPF 页面及包清单检查，尚未打开，等待用户切换验收。全部测试使用合成禁用任务及独立未登录目录，不发送模型请求；数量、报告和真实续跑的未验收边界见 [自动续跑验证记录](AUTO-RESUME-QA.md)。以下已发布版本及历史记录不能代替本轮验收。

Mac 现已随 [preview.16](https://github.com/feifeigong/ai-first-tools/releases/tag/v0.4.0-macos-preview.16) 完整内置同一工具。Apple 芯片和 Intel 各安装一个对应工具箱 APP；侧栏使用总开关和「登录后自动开启」。后台使用包内运行组件，退出窗口后继续运行；关闭总开关停止后台并取消登录自启，移除应用后后台监测退出并清理自身登录项。两架构真实冻结进程、launchd、Cocoa 页面和独立发布核验通过，边界与证据见 [Mac 验证记录](MACOS-QA.md)。下面保留 Windows 实现和历史验证记录。

Windows v0.3.12 起，「Codex 自动续跑」是完整内置工具：后台代码、Python 运行组件、锁定版本的 Codex 原生组件均由工具箱安装包提供。不要求用户安装独立续跑程序、Python、Node 或 Codex CLI。沿用本机已有 Codex 账号及会话，保留原额度判断、会话发现和续跑逻辑。

安装器只创建一个工具箱入口和一个卸载项，后台没有独立的桌面入口或额外安装流程。首次使用默认关闭。工具箱开关以包内后台为标准入口；首次升级发现可识别旧后台时，保留原运行与自启选择并自动接管为内置后台。旧开机入口通过已有偏好检查停用，避免重复常驻。

新后台的开机入口采用当前用户的 Run 项，不需要修改高权限的计划任务。更新前保存运行状态并停止自身后台，更新后恢复；卸载时先停止后台、清理自己的开机项，再按发布清单删除程序。用户配置和 Codex 会话不写入安装包，也不会因卸载而删除。

完整包已随 [v0.3.12](https://github.com/feifeigong/ai-first-tools/releases/tag/v0.3.12) 公开。干净 Windows 安装、实际后台启停与防拉起、运行中覆盖、卸载及独立发布下载核验均通过，范围和证据见 [Windows 验收记录](UPDATER-QA.md)。

下面的早期验证记录保留，用于说明控制页从连接旧程序到完整内置的演进；旧版本的外部依赖不适用于新版安装包。

- 自动续跑开关：开启已有后台程序；关闭时先禁用计划任务和启动文件，停止对应的 VBS 守护，再按完整命令确认并停止 watcher。关闭同时取消开机自启，防止被再次拉起。
- 开机自动开启：单独控制下次登录的启动入口，不启动或停止当前 watcher；优先复用原计划任务，无任务注册权限时沿用启动文件方式。原任务不允许普通用户修改时，使用原工具入口的 `allow_background_watch` 检查：读取本机开机偏好，关闭时直接正常退出，不启动续跑逻辑、不更改任务权限。
- 退出工具箱只关闭控制页，不发送停止 watcher 的指令。设置变更进行中会等待结果再退出。
- 页面打开时读取实际状态，可手动刷新，可见时每 30 秒更新。状态读取失败时不显示缓存为当前状态，禁用操作并保留刷新入口。

路径从原计划任务、真实 watcher 命令、启动文件或本机连接记录发现，源码不包含用户安装路径。连接记录仅保存 Python 和原工具入口位置；开机偏好单独保存为 `auto-resume-startup.json`。不读取认证、聊天、数据库或原配置。停止前重新核对命令，不读 PID 文件、不结束整个进程树、不关闭 Codex。工具箱显式开启时仅对子进程设置 `AI_FIRST_MANUAL_WATCH=1`，因此开机自启关闭时仍能手动开启当前运行。

已存在但无法确认属于原工具的同名计划任务会拒绝修改。读取状态不写入设置；点击开关后才保存连接记录。该页只控制当前 Windows 本机安装，未增加 Mac 入口或在线发布。
