# Codex 自动续跑控制页

Windows v0.3.12 起，「Codex 自动续跑」是完整内置工具：后台代码、Python 运行组件、锁定版本的 Codex 原生组件均由工作台安装包提供。不要求用户安装独立续跑程序、Python、Node 或 Codex CLI。沿用本机已有 Codex 账号及会话，保留原额度判断、会话发现和续跑逻辑。

安装器只创建一个工作台入口和一个卸载项，后台没有独立的桌面入口或额外安装流程。首次使用默认关闭。工作台开关以包内后台为标准入口；首次升级发现可识别旧后台时，保留原运行与自启选择并自动接管为内置后台。旧开机入口通过已有偏好检查停用，避免重复常驻。

新后台的开机入口采用当前用户的 Run 项，不需要修改高权限的计划任务。更新前保存运行状态并停止自身后台，更新后恢复；卸载时先停止后台、清理自己的开机项，再按发布清单删除程序。用户配置和 Codex 会话不写入安装包，也不会因卸载而删除。

完整包已随 [v0.3.12](https://github.com/feifeigong/ai-first-tools/releases/tag/v0.3.12) 公开。干净 Windows 安装、实际后台启停与防拉起、运行中覆盖、卸载及独立发布下载核验均通过，范围和证据见 [Windows 验收记录](UPDATER-QA.md)。

下面的早期验证记录保留，用于说明控制页从连接旧程序到完整内置的演进；旧版本的外部依赖不适用于新版安装包。

- 自动续跑开关：开启已有后台程序；关闭时先禁用计划任务和启动文件，停止对应的 VBS 守护，再按完整命令确认并停止 watcher。关闭同时取消开机自启，防止被再次拉起。
- 开机自动开启：单独控制下次登录的启动入口，不启动或停止当前 watcher；优先复用原计划任务，无任务注册权限时沿用启动文件方式。原任务不允许普通用户修改时，使用原工具入口的 `allow_background_watch` 检查：读取本机开机偏好，关闭时直接正常退出，不启动续跑逻辑、不更改任务权限。
- 退出工作台只关闭控制页，不发送停止 watcher 的指令。设置变更进行中会等待结果再退出。
- 页面打开时读取实际状态，可手动刷新，可见时每 30 秒更新。状态读取失败时不显示缓存为当前状态，禁用操作并保留刷新入口。

路径从原计划任务、真实 watcher 命令、启动文件或本机连接记录发现，源码不包含用户安装路径。连接记录仅保存 Python 和原工具入口位置；开机偏好单独保存为 `auto-resume-startup.json`。不读取认证、聊天、数据库或原配置。停止前重新核对命令，不读 PID 文件、不结束整个进程树、不关闭 Codex。工作台显式开启时仅对子进程设置 `AI_FIRST_MANUAL_WATCH=1`，因此开机自启关闭时仍能手动开启当前运行。

已存在但无法确认属于原工具的同名计划任务会拒绝修改。读取状态不写入设置；点击开关后才保存连接记录。该页只控制当前 Windows 本机安装，未增加 Mac 入口或在线发布。

## 2026-10-16 本机验证

- WPF 发布编译成功，67 项隔离自检通过（含原 62 项和 5 项控制页检查）。
- Windows PowerShell 5.1 的 10 项隔离控制检查通过：真实状态映射、停止顺序、无关进程保护、重复开启、停止后开启、开机设置独立、受保护任务的入口检查、冲突任务拒绝、无效安装拒绝及 Unicode 启动文件。
- 原生桌面窗口检查确认入口与两个开关正常显示；真实状态只读核对为一个 watcher、开机任务启用。手点刷新与侧栏收起/展开通过。
- 原生窗口实际点击开机开关，首次复现原任务 Access denied，补充原入口检查后实测关闭/开启均成功；两次核对仍为同一个 watcher，没有重启后台或请求模型。
- 原续跑工具新增 3 项入口检查单测，全部 50 项隔离测试通过。额度、会话、重置卡和续跑算法未修改，只有 `run.py` 启动前增加开机偏好检查。
- 停止和开启 watcher 的动作通过合成进程/任务替身验证；没有为了验证而重置真实额度、提交真实续跑消息或反复开关真实 watcher。
- 最终采用与原安装一致的自包含包；实际安装目录 67 项自检通过，修复了把依赖系统运行环境的构建覆盖到自包含目录导致无法启动的问题。没有另装系统运行组件。
