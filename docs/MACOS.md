# Mac 版：下载安装与使用

Mac 预览版通过 GitHub 发布，不上苹果商店，不使用 Developer ID 签名或苹果公证。

## 下载与安装

[Mac 发布页](https://github.com/feifeigong/ai-first-tools/releases?q=macos&expanded=true)

1. 苹果 M 系列选 `macos-arm64.dmg`；Intel Mac 选 `macos-x86_64.dmg`。苹果菜单 → 关于本机可以查看芯片类型。
2. 打开 DMG，把「AI一手工具工作台」拖到「Applications / 应用程序」。
3. 在应用程序中打开工作台，点「对话搬家」使用。可以保留在 Dock。

不需要源码、终端、Python、Rust、.NET 或 WebView2。不要下载 Windows EXE 或 Source code。

以 macOS 13 及以上为兼容目标，首批实际打包和窗口检查在 macOS 15；较早系统尚待验收。系统提示不兼容时请记录版本，不强行运行。

## 未签名的首次打开提示

作者选择不签名、不公证，首次打开可能被拦截，不能保证和已签名应用一样顺畅；软件未经过苹果公证或审核。

仅在确认来自本项目并核对发布校验值后，按 [苹果官方流程](https://support.apple.com/zh-cn/102445) 处理：先尝试打开，再到「系统设置 → 隐私与安全性」查看是否有针对该应用的「仍要打开」。不同系统版本、公司管理的电脑可能不同。

提示恶意软件、损坏或没有允许打开选项时，请停止并反馈。不要关闭 Gatekeeper/杀毒软件，不执行不明来源的解锁命令。

## 更新与卸载

- 启动后后台检查 GitHub，也可点「检查更新」；只查询公开版本，不上传对话、认证或本机路径。
- preview.2 使用 Mac 系统证书与系统代理，不要求电脑另外安装 Python 的证书。连接失败会区分超时、证书、地址解析或限流，并提供「打开下载页」，不把失败说成已经最新。
- preview.3 起，有新版会自动出现「下载并更新」。点一次即可在软件里下载、校验，等待搬运结束后自动更新并重新打开，不需要再拖拽或重新安装。preview.8 在启动约两秒后检查，持续打开每十分钟补查；返回窗口、恢复网络或页面重新可见时补查，至少间隔两分钟，且遵守失败退避。检查失败不是「已经最新」，也能手动检查。
- 下载时可以继续使用或取消。应用只接受本项目、当前芯片且校验文件完整的更新；验证失败保留当前版本，替换失败尝试恢复，旧版备份保留，不删除 Agent 数据。
- **preview.1/2 没有一键覆盖功能，需最后一次手动替换到 preview.11；preview.3 及之后可直接在软件里升级。** 旧版自动提醒不出现时先点一次「检查更新」取得本版；旧程序不会随仓库代码提交自动改变。Windows v0.3.7 起已经支持一键下载更新，v0.3.8 统一按钮名称。
- preview.4 调整 WebKit 启动，改善更新后偶发页面未加载的问题；保持随机本机端口和严格 HTTPS，不读取其他 Agent 的浏览器登录数据。重复原生构建及验证边界见 [测试记录](MACOS-QA.md)。
- preview.6 修复自动检查失败被隐藏、长时间不补查的问题：失败会提示并自动重试，恢复连接后自动出现更新按钮。初始化等待本机组件就绪后再检查更新。不是每次重试都弹提示，不会偷偷下载安装；仍需用户点一次「下载并更新」。
- 请从「应用程序」或自己可写的正常安装目录打开。在 DMG、系统隔离运行位置、不可写目录或不支持安全交换的磁盘中，不强行更新，会提示先处理安装位置/权限。系统安全策略可能仍要求用户确认，不关闭系统保护。
- 卸载只把工作台移到废纸篓，不需要删除其他 AI 软件的记录。

## 能力与边界

preview.10 为下载后的更新准备增加八步状态、已用时间、共用三分钟预算及可响应取消的校验/复制操作。取消确认前会显示“正在取消”；异常时保留当前应用，已停止任务的暂存文件在后台清理。预算不包含下载和故障清理，不能保证系统单次磁盘调用异常阻塞时严格按秒返回。若旧程序已经卡住且取消无效，在没有搬家任务时正常退出，再手动安装本版；发布新版本不会改变当前运行的旧更新器。

若顶部仍显示 preview.8、画面只有“正在校验更新包”而没有步骤与秒数，修复版尚未安装成功。请用浏览器从本项目发布页下载完整 DMG，退出旧工作台后将 APP 拖入「应用程序」，选择替换；随后推出 DMG，从 Finder → 应用程序打开工作台，以顶部显示 preview.11 为准。仅点击旧版里的「下载并更新」不会绕过它已经卡住的准备流程。

工作台页面由 Cocoa 直接读取安装包内的静态资源，文件读取范围仅限页面资源目录；更新检查和下载仍使用系统信任库验证 HTTPS。

preview.9 修复 Cursor 搬到本机 Work/Codex 后，发送消息出现 `maximum length 64 ... length 85` 的历史兼容问题。旧版保留的工具调用编号或工具名称可能超过续聊接口限制；新版为这些字段生成稳定、唯一且成对的兼容编号，保留原字段供核对，不截断对话正文、工具参数或结果。

preview.9/10 增加的配对检查过严：Cursor 历史里被取消或中断的工具操作可能一直没有返回，之前会因此拒绝整条对话。preview.11 将缺少调用、缺少返回或编号重用无法确定配对的工具日志完整保存为明确标注的历史说明，保留全部原始字段，既不编造执行结果，也不把它们当成待执行请求。完整配对的工具记录仍做 64 字符兼容处理；结果页会显示保留为历史说明的日志数量。未知结构、类型不匹配和正文完整性错误仍会停止导入。

**遇到长度错误或“历史工具调用缺少配对结果”时，更新至 preview.11 后，从 Cursor 将同一条记录重新搬一次，再打开新副本续聊。** 新版允许旧格式记录重搬一次，保留源记录与旧副本；升级应用不会改写已经搬入的旧历史。续聊回归使用原生引擎和本机模拟服务，不请求在线模型；这与用户真实 Mac 的界面和账号续聊验收分开。

preview.7 修正本机 Work/Codex 长对话的分页导入。旧版只校验短对话回读，导入的是旧式历史，逐条分页接口不能读取；新版同时保留模型上下文与可分页显示记录、稳定轮次/消息编号、连续记录序号，完整校验正文后再登记成功。

**已用旧版搬过但向上翻页失败的记录，请更新工作台，再从 Cursor 重新搬一次。** 新版允许这一次重搬，产生新副本，之后恢复去重；不会删除原 Cursor 记录或修改已搬入的旧副本。打开新的那条记录查看；不要继续查看旧的残缺副本。建议先完全退出 ChatGPT，再重新打开，让它加载新记录。不需清空历史或手动删除数据库。

使用新版 ChatGPT 桌面端的本机 Work/Codex。目标原生引擎的分页读取验证与实际 Mac 桌面界面人工验收是不同层次，边界见 [测试记录](MACOS-QA.md)。本项目不会代用户发送模型请求或测试付费续聊。

Mac 用一个 Cocoa/WebKit 窗口直接显示工作台和工具，不启动另一个窗口再合并。共用原有来源读取、目标模式、搬运、去重、关闭保护和实际 Agent Logo。

- 适配 Application Support、POSIX 路径、原生引擎、打开文件夹和本机任务链接。
- 目标按本机数据与原生结构检查，不因移植伪造支持。ChatGPT 本机 Work/Codex 与云端分开，Claude Cowork/Claude Code 与普通聊天分开。
- 豆包、Hermes、普通云端聊天不作为可写目标；OpenCode 需要另有原生 CLI，不偷偷安装。
- 豆包工作从 Mac 的 `~/Library/Application Support/DoubaoWork/Default/` 读取会话列表和本机轨迹，修复首版误用 Windows 的 `User Data/Default/`。只有本机存在的任务能搬出；纯云端对话仍不可搬运。打开来源软件后可以点右上角刷新，重新寻找来源，无需重启工作台。
- 不迁移项目文件、附件、登录状态、模型权限和运行环境。
- **回读通过不等于所有原生软件实际显示和下一轮对话通过。** 见 [测试记录](MACOS-QA.md)。

如果旧版「检查更新」无法连接，请直接到上面的发布页完成这一次升级。新版仍提示连接失败时，反馈完整提示文字即可；浏览器也无法打开 GitHub 时，需要先检查本机网络，应用不能保证绕过网络限制。更新机制和验证边界见 [Mac 软件内更新](MACOS-UPDATES.md)。
